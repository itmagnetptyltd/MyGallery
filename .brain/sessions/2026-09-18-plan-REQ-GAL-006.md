## What must be true

1. Downloading a Photo **delivers a file**.
2. It delivers **that** Photo, not another one in the Gallery.
3. The delivered file is **byte-for-byte identical** to the file uploaded.
4. A Photo uploaded as `IMG_1234.jpg` is delivered as **`IMG_1234.jpg`**.
5. Where the uploaded filename **cannot be used**, the delivered name still ends
   in the extension of that Photo's image format.
6. An unknown identifier delivers **no file** and does not report success.

## The security crux, stated plainly

Criterion 4 requires the **caller's filename** — untrusted input, kept since
Upload — to be echoed back in a `Content-Disposition` header. Every other slice
has been able to treat that string as inert data; this one cannot.

Two things follow, and they are the reason this slice is more delicate than its
six criteria suggest:

- **The filename is still never a path.** `REQ-GAL-002` is satisfied because
  the file on disk is named for the identifier; nothing here changes that. The
  stored name is used *only* as a header value.
- **The header is built by Werkzeug, not by hand.** `send_file(...,
  as_attachment=True, download_name=...)` applies RFC 5987 encoding and escapes
  the value. Hand-assembling `Content-Disposition: attachment; filename="..."`
  is exactly where a newline in a filename becomes header injection, and where
  a quote breaks the parse. We will not write that string ourselves.

Criterion 5 is the escape hatch the client's own requirement provides, and
`download_name()` is where it lives.

## Approach

One pure function, `mygallery/photos/download.py::download_name(filename,
image_format, photo_id)`, decides what the delivered file is called. It is pure
and has no Flask in it, so every branch of criteria 4 and 5 is testable at belt
A without an HTTP request.

A filename is **refused** and replaced by `<identifier><extension>` when it is
empty after stripping, contains a path separator or `..`, or contains any
control character. Otherwise it is kept as given.

`GET /api/photos/<id>/download` serves the stored bytes with that name as an
attachment. The read is shared with `GET /api/photos/<id>` through one helper,
per the note left at that route, so the two cannot drift apart on what "the
Photo" means.

In the browser, the Larger view gains a Download control beside Delete — an
anchor to that route, which is all a download needs and keeps it working with
the `default-src 'self'` policy.

## Decisions this forces

**None that warrant an ADR.** The route shape and the control's placement are
trivially reversible. `download_name()`'s rule is security-relevant but is one
pure function with its whole behaviour pinned by seven belt-A tests — changing
it is an edit, not a migration.

## What I am unsure about

- **"Cannot be used as delivered" is not defined by the requirement, and I am
  defining it.** Empty, path separators, `..`, control characters. That set is
  a judgement: it covers the cases that are unsafe or meaningless, and leaves
  alone anything merely unusual. If the client meant something narrower or
  wider, the tests say exactly what was assumed and are cheap to change.
- **Windows reserved device names are not handled, and the client is on
  Windows.** A Photo uploaded as `CON.jpg` or `NUL.png` will be delivered under
  that name, and Windows will refuse to save it. No criterion mentions it, so I
  am not building it — but it is a real way criterion 1 could fail on the
  client's own machine, and it is worth knowing before they find it.
- **Non-ASCII filenames are delegated to Werkzeug.** A Photo named `фото.jpg`
  should survive via RFC 5987. I intend to trust the library rather than test
  every encoding, and will say so rather than implying broader coverage.
- **Criterion 3 may pass on arrival at belt C**, because the stored bytes have
  been untouched since slice 2. If it does, it will be made to fail
  deliberately before being trusted — the same treatment the durability tests
  got in slice 4.
- **The Download control's placement repeats slice 4's open question.** It sits
  in the Larger view beside Delete, on the same reading of the brief. Still
  worth one sentence to the client, and still cheap to move.
